# 01 设计原则与约束

> 本文档定义本项目从设计到实现必须遵循的原则与硬性约束，是后续所有架构决策、代码评审、变更评估的判定依据。

## 1. 文档目的

- 明确项目定位与边界，避免范围蔓延和补丁式修复。
- 固化技术选型与分层纪律，保证多人协作下代码风格与结构一致。
- 让"为什么这么做"有据可查，而不是依赖口头约定。

## 2. 项目定位

**合同风险扫描平台（企业级）**。

- 当前阶段（Phase 1）：钉钉登录 + 超管配置中心（钉钉配置可配置化）。
- 后续阶段：合同上传解析、风险扫描规则、AI 分析、报告与钉钉消息通知。

本项目面向企业内部使用，须满足企业级要求：规范、安全、可审计、可维护、可扩展。

## 3. 设计原则

| 编号 | 原则 | 落地点 |
| --- | --- | --- |
| P1 | **分层清晰、单向依赖** | API → Service → Repository → Domain；禁止反向与跨层调用；依赖通过依赖注入（DI）管理 |
| P2 | **接口先行、契约明确** | 先定义接口 / DTO / 错误码，再实现；OpenAPI 作为前后端契约 |
| P3 | **配置外部化、运行时可配置** | 连接凭据仅存环境变量（.env）；业务可配置项入数据库，由超管通过配置页维护 |
| P4 | **安全默认** | 最小权限、密钥加密存储、OAuth state 防护、限流、审计日志 |
| P5 | **可观测** | 结构化日志、request_id 全链路、登录/操作审计全覆盖 |
| P6 | **数据一致性** | Service 层明确事务边界，数据库约束兜底，软删除 |
| P7 | **可测试** | 分层解耦 + DI，pytest 覆盖核心链路，测试与实现同步交付 |
| P8 | **兼容与演进** | API 版本化、数据库变更走迁移、为扩展预留接口（但不做不存在需求的过度设计） |
| P9 | **规范统一** | 命名、响应格式、错误码、注释风格全项目一致 |
| P10 | **杜绝补丁式修复** | 任何变更走「问题 → 设计 → 评审 → 实现 → 测试」流程，禁止绕过设计直接堆补丁 |

## 4. 硬性约束

1. **技术栈**：见下表，选型一经确定不随意更换；更换须走设计评审。
2. **数据存储**：PostgreSQL 为主库（库名 `contract_risk`），Redis 用于会话/限流/OAuth state/缓存（db 编号通过环境变量配置，如 `REDIS_DB`，代码不硬编码）。
3. **凭据管理**：数据库、Redis 连接信息只通过环境变量注入（`.env` / 部署环境变量），**严禁硬编码、严禁将 `.env` 提交到 git**。
4. **钉钉凭据**：由超管通过配置页维护，入库前必须加密（敏感字段）。
5. **语言与编码**：代码标识符使用英文；注释与文档以中文为主。
6. **部署目标**：企业内网/公网，HTTPS 部署。
7. **版本锁定**：后端依赖以 lock 文件（固定版本）锁定，前端以 package-lock.json 锁定，保证构建可复现。

## 5. 技术栈选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router | 管理后台主流组合，生态成熟 |
| 后端 | Python 3.12 + FastAPI | 异步优先；后续 AI 合同扫描生态最友好 |
| ORM / 迁移 | SQLAlchemy 2.0 + Alembic | 参数化查询、可审计的数据库迁移 |
| 主数据库 | PostgreSQL 16 | 企业级主数据存储 |
| 缓存/会话 | Redis 7 | 会话、限流、OAuth state、配置缓存 |
| 认证 | JWT（access/refresh 分离）+ RBAC | 无状态 access + 可吊销 refresh |
| 测试 | pytest + httpx（AsyncClient） | 单元测试 + 集成测试 |
| 质量工具 | ruff / black / mypy；ESLint / Prettier | 静态检查与格式统一 |
| 部署 | Docker Compose + Nginx（后续阶段） | 前后端分离部署 |

## 6. 架构决策记录（ADR）

每个关键决策在本文档追加一行，记录"背景 → 决策 → 后果"，便于追溯。

| ADR | 决策 | 理由 |
| --- | --- | --- |
| ADR-001 | 单体服务 + 模块化分包（非微服务） | 当前规模单体最简，按业务域分包保留未来拆分能力 |
| ADR-002 | 同步 REST + 统一响应包裹 | 契约清晰、调试直观；后续消息驱动仅在确有异步场景时引入 |
| ADR-003 | JWT + Redis 吊销/轮换 | 兼顾无状态扩展与主动吊销能力 |
| ADR-004 | 钉钉配置入数据库并加密 | 满足"超管配置页配置"需求，同时保证密钥不落明文 |
| ADR-005 | 软删除 + 部分唯一索引 | 数据可恢复、可审计；唯一性约束仍由数据库保证 |
| ADR-006 | 应用账号最小权限（仅 DML），迁移用独立 DDL 账号 | 满足安全评审与最小权限原则 |
| ADR-007 | 非功能指标（性能/可用性/备份）以《09》为基线，部署前对齐企业 SLA | 避免空头承诺 |
