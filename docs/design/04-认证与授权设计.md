# 04 认证与授权设计

## 1. 认证方式总览

| 方式 | 面向对象 | 说明 |
| --- | --- | --- |
| 本地账密登录 | 超管（初始内置） | argon2id 校验；首次登录强制改密；失败限流 |
| 钉钉扫码登录 | 企业用户 | 钉钉 OAuth 2.0 授权码模式；首次登录自动建号 |
| 后续扩展 | — | 企业微信 / 短信等，通过 `sys_user_identity.provider` 扩展，不修改核心流程 |

## 2. 令牌体系（JWT）

| 令牌 | 形式 | 有效期 | 存储 | 说明 |
| --- | --- | --- | --- | --- |
| Access Token | JWT（HS256，预留 RS256 能力） | 30 分钟 | 前端内存（Pinia） | 无状态；携带 `sub`(user_id)、`jti`、`roles`、`permissions`、`exp` |
| Refresh Token | JWT（带 `type=refresh`） | 7 天 | httpOnly Secure Cookie + Redis 记录 | 支持轮换与吊销 |

- 刷新：`POST /auth/refresh` 校验 refresh token 与 Redis 中的 jti 一致 → 签发新 access + 新 refresh（轮换，旧 refresh 作废）。
- 吊销：登出、改密、账号禁用 → 将对应 jti 写入黑名单/删除 Redis 记录。
- 401 处理：前端收到 401 后自动刷新一次并重放；刷新失败则跳转登录页。

## 3. 钉钉登录流程（OAuth 2.0 授权码模式）

### 3.1 登录方式总览

| 方式 | 说明 | 使用场景 |
| --- | --- | --- |
| 内嵌二维码（默认，不跳转） | 登录页内嵌钉钉官方二维码，扫码后经 postMessage 返回 authCode，页面不跳转 | 企业用户唯一登录方式 |
| 超管账密登录 | 本地账密（argon2id） | 超管/运维；通过「超管登录」链接切换 |

> **平台限制**：钉钉内嵌 iframe 模式（`iframe=true`）强制 `needLogin=true` 并跳过本机 PC 客户端检测（`_startLocal`）；钉钉客户端本地服务仅允许 `*.dingtalk.com` 域名访问。因此「本机已登录 → 头像确认」无法在内嵌二维码中实现，本系统仅提供扫码登录。

### 3.2 内嵌二维码登录（默认，不跳转页面）

1. 登录页调用 `GET /auth/dingtalk/authorize-url` 获取完整授权 URL（含一次性 state，Redis TTL 10min）。
2. 前端在授权 URL 后追加 `iframe=true`，由内部组件 `DingtalkQrLogin.vue` 在登录页内创建官方二维码 iframe。
3. 扫码成功后钉钉 iframe 通过 `postMessage` 返回 `{authCode, state}`，登录页直接调用 `POST /auth/dingtalk/callback` 完成登录，不跳转。
4. 组件只识别官方协议消息（`success/redirectUrl`、`success:false/errorMsg`），空原因/无关容器消息忽略；开发环境记录消息（仅 DEV）用于诊断。
5. 失败时展示具体原因 +「重新加载」。

### 3.3 超管本地登录

- 登录页提供「超管登录 →」链接，切换到账密表单。
- 认证流程同第 5 节「本地登录（超管）流程」。

### 3.4 钉钉配置项（超管配置页维护）

| 配置项 | 说明 | 敏感 |
| --- | --- | --- |
| client_id | 钉钉应用 Client ID（原 AppKey） | 否 |
| client_secret | 钉钉应用 Client Secret（原 AppSecret） | **是（加密存储）** |
| corp_id | 企业组织 ID（CorpId）；获取应用 access_token（连通性测试）所需 | 否 |
| redirect_uri | 授权回调地址（白名单） | 否 |
| enabled | 是否启用钉钉登录 | 否 |
| agent_id / corp_id | 预留（后续消息通知用） | corp_id 非敏感、agent_id 非敏感 |

> 配置存在 `sys_config(config_key='dingtalk')`，JSON 键为 `client_id` / `client_secret_enc` / `corp_id` / `redirect_uri` / `enabled` / `updated_at`；`client_secret` 加密存储（键 `client_secret_enc`），读取接口返回时脱敏（如 `abc***xyz`）。

### 3.5 钉钉开发者后台配置步骤（以最新官方文档为准）

1. 登录[钉钉开发者后台](https://open-dev.dingtalk.com/) → **应用开发 → 企业内部应用 → 钉钉应用 → 创建应用**；
2. 在应用详情页 **基础信息 → 凭证与基础信息** 获取 **Client ID** 与 **Client Secret**；企业组织 ID（CorpId）可在钉钉开发者后台首页或应用详情「凭证与基础信息」查看；
3. 在 **开发配置 → 权限管理** 申请接口权限：`Contact.User.Read`（用户资料，必须）、`Contact.User.mobile`（手机号，按需），并确保应用已发布且具备基础调用权限（应用 access_token 所需）；
> 注意：`Client Secret` 必须来自应用详情「凭证与基础信息」中的应用 `Client Secret`；新接口返回 `invalid_client` 时，优先检查：应用是否已发布版本（未发布则凭证不生效）、CorpId 是否与应用所属企业一致、复制时是否带空格。
4. 在 **开发配置 → 安全设置 → 重定向URL（回调域名）** 填入前端域名（如 `http://localhost:5173`），须与本系统「回调地址」同源；
5. 在 **应用发布 → 版本管理与发布** 创建版本、设置应用可见范围并发布（非企业管理员发布需企业管理员审批）；
6. 授权成功回调：`redirect_uri?authCode=xxx&state=xxx`；失败回调：`redirect_uri?error=xxx&state=xxx`。

> 企业内部应用不支持跨组织授权登录，仅组织内成员可通过网页方式登录本系统。
> **本地调试**：钉钉官方文档明确测试阶段可使用 `http://127.0.0.1:8000` / `http://localhost:5173` 作为重定向URL（回调域名）；本系统本地可将回调地址设为 `http://localhost:5173/dingtalk/callback`。生产环境必须替换为公网 HTTPS 域名。若后台拒绝 `localhost`，使用 `127.0.0.1`。

### 3.6 历史配置兼容（数据迁移）

- 早期版本配置 JSON 使用 `app_key` / `app_secret_enc` 键；已通过 Alembic 数据迁移（`rename_dingtalk_config_keys_to_client_id`）转换为 `client_id` / `client_secret_enc`，迁移可回滚。
- 配置服务在读取时对旧键做兼容归一化（`app_key → client_id`、`app_secret_enc → client_secret_enc`），避免迁移前遗留缓存导致读取为空。

## 4. RBAC 权限模型

### 4.1 模型

用户（sys_user）— 多对多 — 角色（sys_role）— 多对多 — 权限（sys_permission）。

### 4.2 权限校验

- 依赖注入：`get_current_user`（解析 access token）→ `require_permission("config:dingtalk:write")`。
- 超管：`is_super_admin=true` 或拥有 `super_admin` 角色，跳过细粒度权限校验。
- 权限编码规范：`模块:动作`（如 `config:dingtalk:read` / `config:dingtalk:write`）。

### 4.3 本阶段权限矩阵

| 端点 | 超管 | 管理员 | 普通用户（钉钉） |
| --- | --- | --- | --- |
| 本地登录 / 钉钉登录 / 令牌刷新 | ✔ | ✔ | ✔ |
| 查看自己信息 /auth/me | ✔ | ✔ | ✔ |
| 钉钉配置 读取 | ✔ | ✖ | ✖ |
| 钉钉配置 写入 / 测试 | ✔ | ✖ | ✖ |
| 用户与角色管理（user:manage） | ✔ | ✔ | ✖（404 隐藏） |
| 登录方式探测 /auth/login-methods | ✔ | ✔ | ✔ |

> 可见性（完全隐藏）：钉钉配置的侧边菜单、首页入口与路由仅对超管可见；用户与角色管理对超管/管理员可见，普通用户不渲染入口，直接访问路由被重定向回首页。API 层：敏感管理接口（钉钉配置读/写/测试）对非超管统一返回 404（Not Found），与不存在路由响应一致，避免接口枚举。
### 4.4 用户与角色管理规则
超管与管理员通过 `user:manage` 管理用户及角色分配，均为敏感接口，普通用户访问统一返回 404（隐藏）。执行以下约束：
1. 禁止操作自己：不允许删除/禁用自己；
2. 保护最后一个超管：不允许删除/禁用/去掉 `super_admin` 角色当前唯一活跃超管；
3. 密码重置后 `must_change_password=true`，下次登录强制改密；
4. 所有写操作（创建/更新/重置密码/删除）均写入操作审计。

## 5. 本地登录（超管）流程

1. `POST /auth/login`：校验用户名+密码（argon2id）。
2. 校验状态（启用/禁用）与 `must_change_password` → 若需改密，返回特定错误码，前端跳转改密页。
3. 校验通过 → 签发令牌、写登录日志、更新 `last_login_at` / `last_login_ip`。
4. 安全：按 IP + 用户名限流；连续失败 N 次临时锁定（Redis 计数）。

## 6. 登录安全策略

| 项 | 策略 |
| --- | --- |
| 密码存储 | argon2id，绝不存明文 |
| 限流 | 登录接口：同 IP 每分钟 ≤ 10 次，同账号连续失败 5 次锁定 15 分钟 |
| 会话 | access 30min / refresh 7d；登出即吊销 |
| 审计 | 登录成功/失败均写 `sys_login_log` |
| 改密 | 首次登录强制改密；改密后吊销所有旧 refresh token |
## 7. 钉钉用户的状态与信息同步

- 每次钉钉登录成功后，同步更新 `display_name`、`avatar_url`、`phone` 到 sys_user，并将 `username` 迁移为钉钉手机号（仅当无其他用户占用时），保证用户信息新鲜。
- 钉钉用户登录时校验 `sys_user.status`：禁用账号拒绝登录（返回 30011）。
- 首次自动建号：`username` 取钉钉手机号（缺失时回退 `dt_<unionid>`），`phone` 同步手机号，默认分配 `user` 角色；「新用户需审批」作为可配置策略后续加入（ADR 记录）。

## 8. 密码策略（本地账号）

- 长度 ≥ 10 位；至少包含小写字母、大写字母、数字、特殊字符中的三类。
- 禁止使用用户名、常见弱密码（字典校验）。
- 首次登录/管理员重置后强制改密（`must_change_password`）。
- 初始超管密码允许临时为弱口令（默认 `admin/123456`，仅用于本地/首次登录），启动时记录告警；首次登录必须改密。生产环境应通过 `ADMIN_PASSWORD` 设置符合策略的强初始密码。
- 历史密码防重用：保留最近 5 次（后续实现）。

## 9. 钉钉应用类型说明（实现注意）

- **企业内部应用**（本系统定位）：authorize URL 的 `client_id` = 应用的 Client ID（原 AppKey），无需 corpid 参数。
- **第三方应用**：`client_id` = corpid，需应用市场发布审核；配置页暂不面向该场景。
- 钉钉官方接口（实现时以官方文档为准）：
  - 授权页：`https://login.dingtalk.com/oauth2/auth`（response_type=code, scope=openid）
  - 换 token：`POST https://api.dingtalk.com/v1.0/oauth2/userAccessToken`（clientId/clientSecret/code/grantType）
  - 用户信息：`GET https://api.dingtalk.com/v1.0/contact/users/me`（请求头 `x-acs-dingtalk-access-token`）
  - 应用凭证（最新推荐）：`POST https://api.dingtalk.com/v1.0/oauth2/{corpId}/token`（body：client_id/client_secret/grant_type=client_credentials）；旧版 `oauth2/accessToken`（appKey/appSecret）已逐步下线，不再使用。
    > 网关域名统一使用 `api.dingtalk.com`（接口路径仍为最新 /v1.0/*）；若 `api.dingtalk.io` 对存量应用返回 `invalid_client` 而 `api.dingtalk.com` 正常，以 `api.dingtalk.com` 为准。
