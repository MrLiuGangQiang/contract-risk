# 06 安全设计

> 安全是企业的底线。本文档定义本项目的安全要求与实现约束，作为开发与评审依据。

## 1. 传输安全

| 项 | 要求 |
| --- | --- |
| HTTPS | 生产环境强制 HTTPS（Nginx 终结 TLS，TLS 1.2+） |
| HSTS | 响应头 `Strict-Transport-Security`，有效期 ≥ 180 天 |
| CORS | 白名单模式；仅允许前端域名；生产环境不带 `credentials` 时不允许通配 |
| 安全响应头 | `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy` 等 |

## 2. 密钥管理

- **凭据分层**：数据库/Redis 连接、加密主密钥等只存在于环境变量（`.env` / 部署平台），不入库、不入 git、不进日志。
- **`.env.example`**：仓库内提供模板，字段说明完整，不含真实值。
- **业务密钥加密**：钉钉 `client_secret` 等入库前用 Fernet（AES-128-CBC + HMAC）加密；加密主密钥来自环境变量 `FERNET_KEY`。
- **密钥轮换**：`FERNET_KEY` 支持多密钥版本（旧密钥可解密、新写入用新密钥），轮换不影响存量数据（后续实现）。
- **最小泄露**：任何日志、异常信息、接口响应不得包含密钥明文；配置读取接口返回掩码。

## 3. 身份与访问安全

| 项 | 要求 |
| --- | --- |
| 密码哈希 | argon2id（OWASP 推荐）；校验失败同样返回统一文案 |
| JWT 签名 | HS256（本阶段）；预留 RS256 私钥签名能力 |
| Access Token | 有效期 30 分钟；携带 `jti` 支持吊销；不含敏感个人信息 |
| Refresh Token | 有效期 7 天；httpOnly Secure Cookie + Redis 记录；轮换使用；可吊销 |
| 吊销场景 | 登出、改密、账号禁用、角色变更（后续） |
| RBAC | 最小权限；超管操作全部审计 |
| 管理接口暴露 | 敏感管理接口（钉钉配置/用户与角色）对非超管返回 404（隐藏），避免接口枚举 |

## 4. OAuth（钉钉）安全

| 风险 | 防护 |
| --- | --- |
| CSRF / 登录劫持 | `state` 随机值 + Redis + 10min TTL + 一次性校验 |
| authCode 泄露 | authCode 仅服务端使用 Client Secret 交换，前端不接触 |
| 回调伪造 | `redirect_uri` 必须与配置完全匹配 |
| 用户信息滥用 | 仅获取登录所需字段（unionId/nick/avatar），不做额外授权请求 |
| 配置缺失 | 未配置/未启用时禁止发起钉钉登录 |

## 5. 应用安全

| 风险 | 防护 |
| --- | --- |
| SQL 注入 | 全量使用 ORM 参数化查询；Repository 层禁止字符串拼接 SQL |
| XSS | 前端默认转义；CSP 头；禁止 `v-html` 渲染不可信内容 |
| CSRF（Cookie 场景） | refresh cookie 使用 `SameSite=Lax` + Secure；写接口校验 Origin/Referer 白名单 |
| 敏感数据泄露 | 日志脱敏中间件（password/token/secret 统一掩码）；接口返回脱敏 |
| 依赖漏洞 | CI 引入 `pip-audit` 与 `npm audit`（Phase 1 收尾配置） |
| 文件上传 | Phase 3 合同上传时细化：类型白名单、大小限制、病毒扫描、对象存储、路径防穿越 |

## 6. 限流与防爆破

| 场景 | 策略 | 实现 |
| --- | --- | --- |
| 登录接口 | 同 IP ≤ 10 次/分钟 | Redis 计数 + 中间件 |
| 账号爆破 | 同账号连续失败 5 次锁定 15 分钟 | Redis 计数 + Service 层校验 |
| 全局 API | 单 IP 限流（后续网关/Nginx） | 部署层 |

## 7. 审计与合规

- **登录日志**：成功/失败均记录（用户、方式、IP、UA、失败原因、trace_id）。
- **操作日志**：超管配置变更等敏感写操作记录请求摘要、结果、耗时、操作人。
- **敏感配置变更**：钉钉配置变更记录变更前后摘要（字段级），便于回溯与告警。
- **数据留存**：日志表按月归档；删除遵循企业合规要求（后续补充）。
- **隐私**：仅采集业务必需的个人信息（姓名、头像、联系方式）；不得采集与业务无关数据。

## 8. 环境隔离

| 环境 | 说明 |
| --- | --- |
| dev | 本地开发，可用示例密钥；禁止使用生产凭据 |
| test | 独立测试库/Redis；自动化测试使用 |
| prod | 生产凭据仅部署平台持有；HTTPS；关闭 `/docs`；DEBUG 关闭 |
## 9. 数据库最小权限

- 应用运行时使用最小权限账号（仅 DML），迁移使用独立账号（DDL），报表使用只读账号（后续）。
- 生产库禁止使用超级用户运行应用；连接凭据走环境变量。

## 10. 备份与恢复安全

- 每日全量备份 + WAL 归档（PITR）；备份加密、异地/对象存储保存。
- 每季度至少一次恢复演练，验证 RTO/RPO。
- 备份访问权限最小化并审计。详见《09-非功能性需求与运维设计》。

## 11. 审计日志保护

- 登录/操作日志只增不改（应用无 UPDATE 路径）；日志表权限限定。
- 定期归档导出；归档文件加校验和/签名防篡改（与合规对齐）。
- 审计日志不得与业务数据同库删除流程混用。

## 12. 上线安全评审清单

- [ ] 默认口令已修改 / 初始超管强制改密生效
- [ ] 生产环境 HTTPS + 安全响应头
- [ ] 钉钉 client_secret 加密存储，日志无密钥
- [ ] 依赖扫描（pip-audit / npm audit）无高危漏洞
- [ ] 数据库最小权限账号、备份策略已配置
- [ ] 限流、锁定策略生效
- [ ] 监控告警已配置（登录失败突增等）
