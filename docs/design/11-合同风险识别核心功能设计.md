# 11 合同风险识别核心功能设计

> Phase 3/4 核心：上传合同 → 提取文本 → 规则匹配 → 输出风险结果。本阶段为单机同步扫描（文件较小、规则为关键词匹配），任务队列/对象存储作为后续增强项。

## 1. 范围与原则

- 支持格式：`.txt`、`.pdf`、`.docx`（旧 `.doc` 不支持，前端提示）；
- 单文件上限：20MB；解析文本上限：5MB；
- 扫描规则：使用**当前用户生效规则**（全局模板 + 个人副本，个人优先）；
- 扫描周期：同步返回，文件解析 + 关键词匹配；
- 数据隔离：用户只能查看/删除自己的合同和风险结果；
- 权限：全部登录用户可上传、扫描、查看自己的合同；不开放跨用户查看。

## 2. 规则匹配引擎

1. 提取纯文本并归一化（去空白、统一大小写）；
2. 对每条启用规则，取 `keywords` 列表，逐个在文本中查找（忽略大小写）；
3. 命中即生成一条风险结果：
   - 记录规则快照：rule_code/rule_name/category(维度)/severity/description/suggestion；
   - 记录 `matched_keywords`；
   - 截取首次命中位置前后 60 字符作为 `snippet`；
4. 结果按 severity（high > medium > low）与 sort_order 排序；
5. 重新扫描：删除该合同旧风险结果，重跑规则后写入（事务内原子替换）。

## 4. 文件解析

- txt：优先 UTF-8，失败回退 GB18030；
- pdf：`pypdf` 逐页 `extract_text()`；
- docx：`python-docx` 提取段落与表格文本；
- 解析失败返回业务错误，不入库；
- 文件保存目录：`UPLOAD_DIR`（默认 `backend/data/contracts`），文件名 = `uuid.原扩展名`。

## 5. API（均需登录；仅本人数据）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/contracts/upload` | 上传合同（multipart `file`），同步扫描并返回结果 |
| GET | `/api/v1/contracts` | 分页列表（page/page_size/keyword/severity） |
| GET | `/api/v1/contracts/{id}` | 合同详情 + 风险列表 |
| POST | `/api/v1/contracts/{id}/rescan` | 重新扫描 |
| DELETE | `/api/v1/contracts/{id}` | 软删除合同（删除风险结果） |

- 上传失败/文件非法：`20002` 参数错误；
- 非本人合同：返回 404（隐藏）；
- 写操作（上传/重扫/删除）写 `sys_operation_log`。

## 6. 前端页面

- 侧边栏新增「合同识别」（所有登录用户）；
- 页面：
  - 上传区（拖拽/选择文件，支持 txt/pdf/docx，≤20MB）；
  - 合同列表：文件名、字符数、风险总数、高/中/低统计、时间、操作（查看/重扫/删除）；
  - 详情：按维度分组展示风险卡片（级别、命中关键词、上下文、建议），支持重新扫描；
- 首页「合同上传（即将上线）」卡片改为可用入口。

## 7. 安全与运维

- 上传文件仅解析文本，不执行内容，防路径穿越（uuid 文件名）；
- 原始文件保存在 `UPLOAD_DIR`，生产应替换为对象存储并定期清理；
- 扫描为同步接口，后续大文件/批量扫描接入任务队列（ADR 记录）。
