# 11 合同风险识别核心功能设计

> Phase 3/4 核心：上传合同 → 提取文本 → 规则匹配 → 输出风险结果。本阶段为单机同步扫描（文件较小、规则为关键词匹配），任务队列/对象存储作为后续增强项。

## 1. 范围与原则

- 支持格式：`.txt`、`.pdf`、`.docx`（旧 `.doc` 不支持，前端提示）；
- 单文件上限：20MB；解析文本上限：5MB；
- 扫描规则：使用**当前用户生效规则**（全局模板 + 个人副本，个人优先）；
- 扫描周期：同步返回，文件解析 + 关键词匹配；
- 数据隔离：用户只能查看/删除自己的合同和风险结果；
- 权限：全部登录用户可上传、扫描、查看自己的合同；不开放跨用户查看。

## 2. 识别引擎（规则 + AI）

### 2.1 规则关键词匹配（基础层，维度并发）

1. 提取纯文本并归一化；规则按维度（project/technology/contract/general）分组；
2. **每个维度为一个独立并发任务**（线程池内并行执行），任务状态（pending/running/done + 规则数 + 命中数）实时写入任务存储，前端展示维度任务卡；
3. 对每条启用规则的关键词逐个查找（忽略大小写），命中生成 `source=rule` 的风险结果（规则快照 + 命中关键词 + 上下文 snippet）；
4. 各维度结果合并后按 severity 与 sort_order 排序。

### 2.2 AI 规则理解与逐条并发校验（核心，可配置，降级安全）

- 接入 **OpenAI 兼容 Chat Completions API**，由超管在「系统配置 → AI 大模型」页面维护（存储于 `sys_config(config_key='ai')`，`api_key` 加密、读取脱敏、支持连通性测试），默认关闭：

### 2.2.1 两阶段校验（先理解合同结构，再逐条规则并发判定）

**阶段一：合同条款拆分（1 次 AI 调用）**
1. AI 通读合同，输出条款清单 `[{index, title, summary}]`（标题 + 摘要，不含全文）；
2. 本地同步把合同按条款边界切成原文 chunk（供证据定位，保证原文保真）；
3. AI 不可用时降级为按段落本地切分。

**阶段二：逐条规则并发校验（每条规则 1 次调用）**
1. 输入：规则原文（rule_text）+ 条款清单（标题/摘要），而非全量合同——token 消耗大幅下降；
2. 输出：`{matched, clause_indices, severity, explanation, suggestion}`；
3. 命中后从 clause_indices 对应原文 chunk 提取 snippet（不再二次调用 AI）；
4. 并发限流 `AI_RULE_CONCURRENCY`（默认 4），逐条状态实时上报；
5. 严重度由 AI 判定（high/medium/low）。

### 2.2.2 降级语义

- AI 未配置/不可用：扫描任务返回明确错误「请先配置 AI 大模型」；
- 单条规则校验失败：该条标记降级，不影响其他规则。

### 2.3 结果合并（报告生成）

1. 四维度规则命中 + AI 流式发现合并；
2. 同 `rule_code` 去重（保留规则命中，AI 仅补充新发现）；
3. 统一按 severity 排序后写入 `sys_contract_risk`，`risk_source` 标记 `rule` / `ai`；
4. 重新扫描：事务内原子替换；
5. **风险报告页**（`/contracts/:id/report`，全宽布局）：顶部粘性导航（返回 + 文件名 + 重扫）→ **风险概览**（总风险/高/中/低计数 + 定性结论，不再使用无依据的数字评分）→ 图表（严重度分布 + 维度分布，辅助）→ **维度筛选条**（不同角色只关注自己领域）→ 风险明细（核心：条款原文定位高亮 + 人话风险解释 + 修改建议）。

## 4. 文件解析

- txt：优先 UTF-8，失败回退 GB18030；
- pdf：`pymupdf` 逐页 `get_text()` 提取文本层；
- docx：`python-docx` 提取段落与表格文本；
- 解析失败返回业务错误，不入库；
- 文件保存目录：`UPLOAD_DIR`（默认 `backend/data/contracts`），文件名 = `uuid.原扩展名`。

### 4.1 扫描版 PDF 视觉识别（OCR）

- **判定**：文本层提取后不足 50 字符即视为扫描版（纯图片）；
- **流程**：`pymupdf` 按 140 DPI 逐页渲染为 PNG → 每页调用 AI 视觉模型（chat/completions image_url）转录为文字 → 4 页并发，按页序拼接为完整文本 → 更新合同文本后进入正常规则+AI 风险识别流程；
- **前提**：需超管已配置并启用 AI（未配置时返回 `20002` 明确提示）；
- **进度**：转录进度以「第 n/N 页（累计转录字符数）」实时写入任务进度；
- **失败处理**：单页转录失败按空文本跳过；全部为空时返回业务错误。

## 5. API（均需登录；仅本人数据）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/contracts/upload` | 上传合同（multipart `file`）：文本解析后合同以「扫描中」状态**立即入库**，后台异步扫描，返回 `{job_id, contract_id}` |
| GET | `/api/v1/contracts/jobs/{job_id}` | 查询任务进度（Redis 存储，前端轮询）；非本人任务 404 |
| GET | `/api/v1/contracts/{id}/job` | 按合同查询其关联的后台扫描进度（列表恢复进度入口） |
| GET | `/api/v1/contracts` | 分页列表（page/page_size/keyword/severity） |
| GET | `/api/v1/contracts/{id}` | 合同详情 + 风险列表 |
| POST | `/api/v1/contracts/{id}/rescan` | 重新扫描：合同置「扫描中」，后台异步任务，返回 `{job_id}` |
| DELETE | `/api/v1/contracts/{id}` | 软删除合同（删除风险结果） |

- 上传失败/文件非法：`20002` 参数错误；
- 非本人合同：返回 404（隐藏）；
- 写操作（上传/重扫/删除）写 `sys_operation_log`。

## 7. 安全与运维

- 上传文件仅解析文本，不执行内容，防路径穿越（uuid 文件名）；
- 原始文件保存在 `UPLOAD_DIR`，生产应替换为对象存储并定期清理；
- 扫描为**后台异步任务**：任务状态存 Redis（`job:contract_scan:{job_id}`，TTL 10min），前端轮询展示阶段进度：读取文件 → 提取文本 → 规则匹配 → AI 分析 → 生成结果；失败返回明确阶段错误。

### 7.0 任务状态结构（Redis）

任务状态（`job:contract_scan:{job_id}`）除基础字段外扩展：

```json
{
  "status": "running",
  "progress": 55,
  "stage": "AI 正在深度分析",
  "tasks": {
    "project":    { "label": "项目管理风险", "status": "done",    "rule_count": 5, "hits": 3 },
    "technology": { "label": "技术风险",     "status": "running", "rule_count": 4, "hits": 0 },
    "contract":   { "label": "合同条款风险", "status": "done",    "rule_count": 4, "hits": 2 },
    "general":    { "label": "通用风险",     "status": "pending", "rule_count": 4, "hits": 0 }
  },
  "ai": { "status": "running", "findings": 0 },
  "events": [{ "time": "10:00:00", "level": "info", "message": "..." }]
}
```

- `tasks`：维度并发任务清单（init 时写入，running/done 实时更新）；
- `ai.status`：`running/skipped/done/failed`；
- AI 流式全文：`job:contract_scan:stream:{job_id}`（追加式，TTL 同任务）。

### 7.1 后台扫描语义

- **上传即入库**：文本解析成功后合同以 `status=3（扫描中）` 立即入库并提交，用户关闭页面 / 刷新页面均不影响扫描继续；解析失败不入库（返回 20002）。
- **合同状态机**：`3 扫描中 → 1 已完成`；任一阶段失败 `3 → 2 失败`（可重新扫描）。
- **进度关联**：任务创建时写入 `job:contract_scan:contract:{contract_id} → job_id` 关联，列表可按合同恢复进度查看（`/contracts/{id}/job`）。
- **孤儿任务恢复**：应用重启后，启动阶段自动恢复所有 `status=3` 的合同（重新发起后台扫描）。
- **重复扫描防护**：扫描中的合同再次触发重扫返回业务错误。
- 前端：列表对扫描中合同展示动效状态并自动轮询刷新；进度弹窗可随时关闭（后台继续执行）。
