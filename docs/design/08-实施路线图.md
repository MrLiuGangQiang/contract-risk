# 08 实施路线图

> 按阶段推进，每阶段有明确范围、验收标准与交付物。**不在当前阶段实现后续阶段功能**（避免过度设计与返工），但设计上已为其预留扩展点。

## Phase 0 — 设计（当前，已完成）

- 输出设计文档（01~07）。
- 验收：设计评审通过，技术栈与分层约束确认。

## Phase 1 — 基础平台 + 钉钉登录（当前目标）

### 范围

1. 项目脚手架：后端（FastAPI 分层骨架）+ 前端（Vue3 + TS + Element Plus）。
2. 基础设施：pydantic-settings 配置、PostgreSQL 连接与 Alembic 初始化、Redis 客户端、结构化日志、全局异常、统一响应、健康检查。
3. 超管本地登录：初始超管创建（环境变量，幂等）、argon2id、强制改密、限流、登录审计。
4. RBAC 骨架：用户/角色/权限模型、种子数据、权限校验依赖。
5. 钉钉配置中心：超管配置页（读取/保存/测试）、`client_secret` 加密存储、脱敏返回、操作审计。
6. 钉钉扫码登录：授权 URL → 回调 → 换取 token → 获取用户信息 → 自动建号 → 签发 JWT 全链路。
7. 测试：登录、钉钉回调、配置读写、权限校验的单元 + 集成测试。
8. 可观测性基础：/metrics（Prometheus 格式）、基础告警规则（与运维对齐后落地）。
9. 备份与运维文档：PostgreSQL 备份脚本与恢复演练说明。

### 验收标准

- 超管可通过本地登录进入系统并完成钉钉配置。
- 配置后，企业用户可通过钉钉扫码登录进入系统（首次自动建号）。
- 未配置/未启用钉钉时，钉钉登录入口被正确拦截并提示。
- 安全：密钥加密、state 校验、限流、审计日志全部生效。

### 交付物

- 可运行的前后端代码 + 测试 + 部署说明（Docker Compose + Nginx）。
- 监控指标与告警配置、备份恢复脚本。

## Phase 2 — 用户与权限管理

- 用户列表/搜索/启用禁用/重置密码。
- 角色管理、角色-权限分配、用户-角色分配。
- 钉钉账号绑定/解绑管理。

## Phase 3 — 合同管理

- 合同上传（类型/大小/病毒扫描）、对象存储、版本管理。
- OCR + 文档解析（PDF/Word），结构化合同数据。

## Phase 4 — 风险扫描

- 规则引擎（可配置风险规则）。
- AI 分析（大模型抽取/判定），风险项管理与复核。

## Phase 5 — 报告与通知

- 风险报告生成/导出。
- 钉钉消息通知（利用 agent_id/corp_id）。
- 数据看板。

## 评审关卡

- 每阶段结束进行设计/实现评审（对照《01-设计原则与约束》与《06-安全设计》上线清单），评审通过方可进入下一阶段。
- 评审记录归档至 docs/ 对应阶段。

## 每阶段通用要求

- 测试同步交付；覆盖率达标。
- 文档同步更新（接口、设计、部署）。
- 代码评审通过后合并。
