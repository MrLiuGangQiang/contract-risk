# 部署指南（Docker Compose + Nginx）

> 对应《09-非功能性需求与运维设计》第 8 节。本文档给出本地/单机容器化部署与镜像发布步骤；生产环境还需结合平台安全基线（HTTPS、密钥托管、备份、监控告警）落地。

## 1. 镜像构建与推送（阿里云 ACR）

本系统为**单一一体化镜像**（Nginx 托管前端 + Uvicorn 后端同容器），仓库：`registry.cn-hangzhou.aliyuncs.com/liugangqiang/contract-risk`。

### 1.1 使用 GitHub Actions（推荐，生产发布走此通道）

- 工作流：`.github/workflows/build-push-acr.yml`。
- 前置：仓库 Secrets 已配置 `ACR_USERNAME`（阿里云账号全名）与 `ACR_PASSWORD`（容器镜像服务访问凭证密码）；ACR 仓库 `liugangqiang/contract-risk` 已创建。
- 触发方式：
  - push `main`：自动构建并推送 `:latest` + `:sha-<7>`；
  - 打标签 `v*`（如 `v0.1.0`）：自动构建并推送 `:v0.1.0` + `:latest` + `:sha-<7>`；
  - 手动（Actions → Build & Push ACR → Run workflow）：可指定 `image_tag`。
- 产物示例：`registry.cn-hangzhou.aliyuncs.com/liugangqiang/contract-risk:v0.1.0`。

### 1.2 本地手动构建（应急/调试通道）

前置条件：

- 已安装 Docker Engine 24+ / Docker Desktop，并启动；
- 已登录 ACR：`docker login registry.cn-hangzhou.aliyuncs.com`（用户名 = 阿里云账号全名，密码 = 容器镜像服务访问凭证密码）；
- ACR 仓库已创建：`liugangqiang/contract-risk`。

构建并推送（版本标签示例 `v0.1.0`）：

```powershell
# Windows PowerShell（仓库根目录执行）
.\scripts\build-and-push.ps1 -Tag v0.1.0
```

等价命令（任意平台）：

```bash
TAG=v0.1.0
REGISTRY=registry.cn-hangzhou.aliyuncs.com/liugangqiang/contract-risk
docker build -t ${REGISTRY}:${TAG} .
docker push ${REGISTRY}:${TAG}
```

镜像说明：单容器内含 Nginx（前端静态资源 + `/api` 反向代理到 `127.0.0.1:8000`）与 Uvicorn（FastAPI + Alembic，Python 3.12-slim）。

## 2. 环境变量（聚合格式）

环境配置采用**聚合格式**（推荐），连接串与连接池参数集中在少量变量：

| 变量 | 说明 |
| --- | --- |
| `DATABASE_URL` | PostgreSQL 聚合连接串，如 `postgresql+asyncpg://app_user:密码@postgres:5432/contract_risk` |
| `REDIS_URL` | Redis 聚合连接串，如 `redis://redis:6379/0`（有密码：`redis://:密码@redis:6379/0`） |
| `JWT_SECRET` | JWT 签名密钥，强随机、长度 ≥ 32 |
| `FERNET_KEY` | 配置加密主密钥，用 `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` 生成 |
| `ADMIN_PASSWORD` | 初始超管密码（首次登录强制改密） |
| `DB_POOL_SIZE` / `DB_MAX_OVERFLOW` / `DB_POOL_TIMEOUT` / `DB_POOL_RECYCLE` / `DB_POOL_PRE_PING` / `DB_ECHO` | 数据库连接池参数（默认 10/20/30/1800/true/false） |
| `REDIS_MAX_CONNECTIONS` | Redis 连接池上限（默认 50） |

> 兼容旧拆分写法：`DATABASE_URL`/`REDIS_URL` 留空时，应用会按 `POSTGRES_HOST/PORT/DB/USER/PASSWORD`、`REDIS_HOST/PORT/DB/PASSWORD` 自动组装；两者同时存在时聚合优先。钉钉配置不需要环境变量，由超管在系统配置页维护。

完整模板见 `backend/.env.example`。

## 3. 本地/单机运行（docker compose）

1. 准备环境变量：复制 `backend/.env.example` 为 `backend/.env`（或根目录 `.env`），至少修改：
   - `DATABASE_URL`：指到 compose 内的 `postgres` 服务（如 `postgresql+asyncpg://app_user:密码@postgres:5432/contract_risk`）；
   - `REDIS_URL`：指到 compose 内的 `redis` 服务（如 `redis://redis:6379/0`）；
   - `JWT_SECRET`、`FERNET_KEY`：强随机值；
   - `ADMIN_PASSWORD`：初始超管密码（首次登录强制改密）；
   - `POSTGRES_PASSWORD`：与 `DATABASE_URL` 中密码一致（postgres 容器初始化用）。
2. 启动：

```bash
docker compose --env-file backend/.env up -d
```

3. 验证：
   - 前端/API 入口：`http://localhost`（Nginx :80，`/api` 自动转发到同容器后端）；
   - 健康检查：`http://localhost/api/v1/health`；
   - 迁移日志：`docker compose logs migrate`。
4. 停止：`docker compose down`（保留数据卷 `pgdata`）；彻底清理：`docker compose down -v`。

## 4. 生产部署注意事项

- HTTPS：由入口网关/负载均衡终止 TLS；Nginx 仅服务 HTTP，`X-Forwarded-Proto` 已透传。
- 迁移：正式发布先执行 `docker compose run --rm migrate`，确认成功后再滚动更新应用；多副本时迁移必须单独执行（勿随容器启动）。
- 多副本：应用为无状态服务可水平扩展（Nginx/Uvicorn 同容器，入口 `:80`）；后端 worker 数通过 `UVICORN_WORKERS` 调整。
- 备份：PostgreSQL 每日 `pg_dump` + WAL 归档；Redis 数据可重建。
- 钉钉回调域名：生产使用公网 HTTPS 域名，并同步配置到钉钉开发者后台（回调域名 + H5 微应用主页）。
- 密钥：生产不要使用 compose 明文 `.env` 持久化敏感值，建议改用部署平台密钥管理（K8s Secret / 云凭据）。
